# Workstream A – EQ / Zielkurve: von Polygonzug zu echtem Sound-Lab

## A1. Aktuellen Fehler korrigieren

Aktuell zeichnet `ui/target_curve.py` die Zielkurve direkt über die Stützpunkte:

`ax.semilogx(self._frequencies, self._levels, ...)`

Dadurch entstehen gerade Segmente und sichtbare Knicke.

Das ist für die gewünschte Darstellung nicht ausreichend.

### Ziel

Die sichtbare Kurve muss mit deutlich höherer Abtastung gerendert werden.

Für **freie Zielkurven-Stützpunkte**:

- Interpolation im `log10(f)`-Raum;
- keine lineare Interpolation im Hz-Raum;
- bevorzugt monotone / formstabile kubische Interpolation, z. B. PCHIP;
- keine unkontrollierten Cubic-Spline-Overshoots;
- 600–1200 Renderpunkte von 20 Hz bis 20 kHz;
- Kontrollpunkte bleiben exakt auf der Kurve;
- Presets und gespeicherte Projekte bleiben kompatibel.

Wenn SciPy-PCHIP verwendet wird, muss ein isolierter Kern-Helper entstehen und getestet werden.

### Abnahme

Ein Ziel mit z. B.

- 20 Hz 0 dB
- 80 Hz +6 dB
- 500 Hz 0 dB
- 4 kHz -3 dB
- 20 kHz 0 dB

muss als glatte Kurve erscheinen, ohne polygonale Ecken und ohne unrealistische Überschwinger.

---

## A2. Parametrische EQ-Bänder nicht mehr als Gauß-Näherung behandeln

`apply_parametric_band()` benutzt aktuell eine Gaußfunktion im Oktavraum.

Für einen modernen EQ soll die sichtbare/technische DSP-Vorschau echte Filterantworten verwenden.

Neues Datenmodell mindestens:

```text
EQBand
- id
- enabled
- filter_type
- frequency_hz
- gain_db
- q
- slope/order optional
```

Filtertypen mindestens:

- Bell / Peaking
- Low Shelf
- High Shelf
- Low Pass
- High Pass

Optional, wenn ohne Scope-Explosion möglich:

- Notch
- Band Pass
- All Pass als spätere Vorbereitung

Mathematik:

- bewährte digitale Biquad-Beziehungen verwenden;
- Sampling-Rate als expliziten Parameter;
- Frequenzantwort als komplexe Antwort berechnen;
- kombinierte Kurve aus allen aktiven Bändern bilden;
- Phase später anschließbar halten.

Keine rein dekorative Kurve.

Für die **Zielkurve** und den **DSP-EQ** zwei Konzepte sauber unterscheiden:

- Zielkurve = gewünschter akustischer Verlauf;
- EQ-Bänder = konkrete Filter, mit denen ein vorhandener Entwurf verändert werden kann.

UI darf beide überlagern, aber intern nicht vermischen.

---

## A3. EQ-Interaktion modernisieren

Aktiver Bereich soll sich wie ein echtes Sound-Tool anfühlen:

- Band-Punkte frei auf der logarithmischen X-Achse ziehen;
- X = Frequenz;
- Y = Gain;
- Mausrad oder alternative Bedienung für Q, falls robust umsetzbar;
- immer numerische Felder als barrierefreie Alternative;
- aktives Band größer/hervorgehoben;
- Tooltip/Inspector mit:
  - Typ
  - Frequenz
  - Gain
  - Q
  - Aktiv
- Doppelklick auf freie Graphfläche kann optional neues Bell-Band erzeugen;
- Rechtsklick / Löschen löscht Band nur nach eindeutigem UI-Verhalten;
- Undo/Redo in den bestehenden History-Ansatz integrieren oder lokales robustes Undo verwenden.

Während Drag:

- nur schnelle Graphvorschau;
- keine schwere Gesamtoptimierung pro Pixel;
- genaue Neuberechnung nach Release / Debounce.

---

## A4. Graph-Design verbessern

Qualitätsziel:

- große dominante Graphfläche;
- Frequenzachse 20 Hz–20 kHz;
- dezente, gut lesbare Gridlines;
- 0-dB-Linie klar;
- Bereiche über/unter 0 dB dürfen dezent gefüllt werden;
- Target, Ist, DSP und Varianten klar unterscheidbar;
- Auswahl nicht ausschließlich durch Farbe ausdrücken;
- Labels nur dort, wo sie helfen;
- kein visuelles Qt-Testtool-Gefühl.

Keine 1:1-Kopie der Slate-Digital-Oberfläche.

---

## A5. Datenlücken sichtbar und verständlich machen

Wenn tatsächliche FRD-Daten nur bis z. B. 5 kHz bekannt sind:

- Zielkurve bleibt 20 Hz–20 kHz vollständig editierbar;
- **Istkurve darf nicht erfunden werden**;
- unbekannter Bereich wird klar als "keine belastbaren Mess-/Herstellerdaten" gekennzeichnet;
- Bibliotheksdetail zeigt, welche Daten fehlen;
- automatische Zielkurvenbewertung bewertet nur belegte Bereiche und weist auf die eingeschränkte Aussagekraft hin.

Das ist mit Workstream C zu koppeln.

## D3. Akustische Wirkung

Keine pauschale "Schaumstoff = +20 % Volumen"-Magie.

Unterscheiden:

### Wall Lining
- geometrisch visualisieren;
- BOM-Fläche berechnen;
- Mindestabstand zu Port/Magnet;
- optional Qa/Verlustmodell nur wenn dokumentiert.

### Bulk Fill
- Menge/Masse berechnen;
- für Closed optional dokumentiertes apparent-volume-/loss-Modell;
- Effekt abschaltbar;
- Vertrauenshinweis in UI.

### Bass Reflex
- keine Füllung direkt vor Port;
- keep-out-Zone;
- Wandbelag statt unkontrollierter dichter Füllung bevorzugen;
- Warnung bei Portblockade.

### Transmission Line
- Füllposition entlang des Pfades;
- später positionsabhängiges Dämpfungsmodell;
- in diesem Sprint mindestens Datenmodell, Geometrie und BOM sauber.

---

## D4. Automatische Empfehlung

- sealed: Wandbelag bzw. Füllung abhängig vom Modell;

- bandpass: kammerbezogen;
- TL/Horn: nur wenn Solver/Modell das sinnvoll kennt, sonst "manuell prüfen".

Empfehlung ist editierbar.

# Workstream F – Komponentenwerte für Weichen und EQ vollständig definieren

Der Nutzer bemängelt, dass der EQ über den ganzen Bereich sichtbar ist, aber viele Werte/Komponenten nur teilweise definiert sind.

Das Problem hat zwei Ursachen und beide müssen getrennt gelöst werden:

1. **Graph/Target:** Ziel ist überall definiert.
2. **Ist-/Komponentenwissen:** reale Treiber-/Weichendaten können fehlen.

## F1. Filterwerte

Für jedes Filterband:

- Typ
- Frequenz
- Gain
- Q
- Sampling Rate
- Aktivstatus

müssen eindeutig sein.

Keine "Punkte ohne technische Bedeutung".

## F2. Passive Weiche

Bibliothekswerte ergänzen:

- nominaler Wert
- E-Reihe
- Toleranz
- Spannungs-/Leistungsrating
- DCR bei Spulen
- optional Hersteller/SKU/Preis

Wenn nur theoretischer Sollwert:

UI zeigt "berechnet".

Wenn konkretes Bibliotheksteil:

UI zeigt "gewähltes Bauteil".

# Acceptance Criteria

## EQ

- [ ] Zielkurve wird visuell glatt mit hochauflösender Kurve gerendert.
- [ ] Keine geraden Polygonsegmente zwischen den sichtbaren Kontrollpunkten.
- [ ] Kontrollpunkte bleiben exakt definiert.
- [ ] Parametrische Bänder besitzen echte Filterparameter.
- [ ] Bell/Shelf/HP/LP haben berechnete Frequenzantwort.
- [ ] Mehrere Bänder werden korrekt kombiniert.
- [ ] aktives Band zeigt Frequenz/Gain/Q/Typ.
- [ ] Maus und numerische Bedienung funktionieren.
- [ ] Undo funktioniert.
- [ ] Ziel/Ist/DSP/Varianten sind visuell eindeutig getrennt.
- [ ] unbekannte Ist-Bereiche werden nicht erfunden.

## UI

- [ ] Standardmodus ist sichtbar ruhiger als V3.2.
- [ ] Technische Rohparameter dominieren nicht die Planungsansicht.
- [ ] Klangbereich ist eine echte Arbeitsfläche, kein Formular mit kleinem Plot.
- [ ] 3D & Konstruktion besitzt eine dominante Visualisierung.
- [ ] Sekundärfunktionen verdrängen die primäre Navigation nicht.

## Library

- [ ] Readiness/Completeness existiert.
- [ ] Library Detail zeigt fehlende Daten nachvollziehbar.
- [ ] Coverage-Report vorhanden.
- [ ] Datenbasis wurde auf echte Vollständigkeitslücken geprüft.
- [ ] zusätzliche reale Daten nur mit Quellenbeleg.
- [ ] EQ-/Fullrange-Workflow berücksichtigt Datenqualität.
- [ ] akustische Behandlung als Kategorie vorhanden.

## Damping

- [ ] Schaumstoff/Vlies/Füllung ist ein Projektobjekt.
- [ ] Position und Menge sind gespeichert.
- [ ] Port-Keepout vorhanden.
- [ ] Closed/Bassreflex erhalten sinnvolle unterschiedliche Regeln.
- [ ] Behandlung erscheint in BOM.
- [ ] Behandlung erscheint in Bauanleitung.
- [ ] Behandlung wird in Zeichnung oder 3D sichtbar.
- [ ] keine unbelegte akustische Wirkung wird als exakt dargestellt.

## 3D

- [ ] UI-unabhängiges Scene Model.
- [ ] interaktive 3D-Vorschau.
- [ ] Gehäuseplatten sichtbar.
- [ ] Treiber sichtbar.
- [ ] Port/PR sichtbar.
- [ ] Streben/Trennwände sichtbar.
- [ ] Dämmung sichtbar.
- [ ] mindestens Closed und Bassreflex funktionieren.
- [ ] 3D nutzt dieselben Projekt-/Geometriedaten wie Zeichnung/BOM.

## Quality

- [ ] bestehende Tests bleiben grün.
- [ ] neue Core-Module mypy-strict.
- [ ] Ruff sauber.
- [ ] keine künstlichen Herstellerdaten.
- [ ] kein stilles Ersetzen von NOT_RUN durch PASS.
- [ ] Build Report geschrieben.
- [ ] Handoff vollständig.

## Do Not Modify / Do Not Regress

- keine erfundenen T/S-/FRD-/ZMA-/Montagedaten;
- keine Absenkung bestehender Solverwarnungen, nur um Varianten häufiger "machbar" zu machen;
- keine Entfernung des Expertenmodus;
- keine zweite konkurrierende Projektmodellstruktur;
- keine eigene Geometrie nur für 3D, die von Zeichnungen/BOM abweicht;
- keine harte Abhängigkeit des Kernmodells von PySide6;
- keine Cloudpflicht;
- keine automatische Veröffentlichung;
- keine 1:1-Kopie fremder kommerzieller EQ-Oberflächen.

---

## Known Risks / Limitations

- Ein glatter Zielgraph löst fehlende reale FRD-Daten nicht; Library Readiness muss das transparent machen.
- Hersteller liefern FRD/ZMA häufig nicht als maschinenlesbare Dateien.
- Dämmmaterialwirkung ist stark material-/dichte-/positionsabhängig.
- Eine vollständige CAD-/Boolean-Engine ist größer als dieser Sprint.
- Hersteller-3D-Modelle fehlen häufig; parametrische Ersatzgeometrie bleibt eine Näherung.
- Windows-/DPI-Sichttest kann in einer Linux-/Offscreen-Umgebung NOT_RUN bleiben.
