3D darf nicht nur hübsch aussehen. Geometrie, Kollision, Zeichnung, BOM und später STEP müssen auf demselben parametrischen Kern beruhen.

# Architekturregeln

- Core/Domain darf nicht von PySide6 abhängen.
- Solver, Optimierer, Library und Geometrie bleiben separat testbar.
- Einheiten intern SI.
- UI formatiert Werte und Einheiten.
- Projektdatei erhält bei Schemaänderungen Migrationen.
- Ein einziges kanonisches Projektmodell.
- Keine doppelte Geometrie für UI und Fertigung.
- Datenprovenienz bleibt erhalten.
- Fehlerzustände werden als strukturierte Objekte modelliert, nicht nur als freie Strings.
- Ergebnisse müssen reproduzierbar sein.
- Zufallsbasierte Optimierung nur mit explizitem Seed und dokumentierter Deterministik.

# Detailed Execution Extension

## User Journeys

### Journey 1 – Mechanical feasibility before export
A driver physically fits the front cutout but its magnet collides with a window brace. The design is marked mechanically invalid, the collision is highlighted in 3D and manufacturing export is blocked.

### Journey 2 – Joinery change
Switch rear panel from butt joint to rebate. Panel dimensions, net volume, cut list, drawing and 3D all update from the same geometry.

### Journey 3 – Transparent inspection
User hides front/side panels, sees port, braces, crossover and acoustic treatment, clicks an object and receives exact dimensions/source confidence in the inspector.

## Geometry Precision Policy

Define model tolerances:
- geometric epsilon
- collision contact vs overlap
- minimum manufacturing clearance
- display tessellation tolerance

Never use viewport mesh approximation as the authoritative manufacturing geometry.

## Scene / Solid Separation

The renderer may consume triangulated/display geometry, but authoritative geometry remains the canonical panel/solid feature model. STEP/DXF and collision must not depend on screen tessellation.

## Collision Severity

Classify:
- hard collision
- insufficient clearance
- near-edge manufacturing warning
- unknown due to missing component envelope

Unknown geometry must not become "clearance passed".

## Selection Contract

Every selectable 3D object maps to a stable project entity ID. Selection must survive camera changes and should survive recomputation when the same entity still exists.

## Performance Benchmarks

Measure:
- scene build;
- collision pass;
- viewport update;
- section/explode;
- complex 3-way enclosure.

## Additional Evidence

- deliberate brace/driver collision;
- port/back-wall clearance;
- rebated panel section;
- transparent internal view;
- object selection + inspector.

## Additional Acceptance

- [ ] Collision engine works without PySide.
- [ ] Display mesh is not the manufacturing source of truth.
- [ ] Unknown component geometry cannot produce false PASS.
- [ ] Joinery changes propagate to volume/cutlist.
- [ ] Stable entity IDs connect 3D, BOM, warnings and drawings.

## 3. Unknown / Missing / Partial Data Matrix

The implementation must explicitly consider these states:

### Known and verified
Value has sufficient source/trust and may participate fully.

### Known but lower trust
Value exists but source or model confidence is limited. It may participate with reduced confidence and a visible status.

### Derived
Value was calculated from other inputs. The derivation and model version must remain recoverable.

### User override
Value was manually supplied. It must not masquerade as manufacturer data.

### Missing
No value. Do not substitute 0, empty string interpreted as zero, or arbitrary default if that would change engineering meaning.

### Not applicable
The field/metric does not apply to this component/system.

### Unsupported
The program currently cannot calculate the metric for this configuration.

Every new result/UI field must map cleanly to one of these states.
