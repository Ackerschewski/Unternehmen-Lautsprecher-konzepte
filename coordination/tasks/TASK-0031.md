# Warum dieses Paket nötig ist

Die Automatik ist nur so gut wie die Bibliothek. Ziel ist eine große, qualitativ bewertete, quellenfeste Komponentenbasis statt vieler halbleerer Einträge.

Der aktuelle Stand ist bereits funktionsreich. Der nächste Qualitätssprung entsteht nicht durch weitere isolierte Buttons, sondern durch belastbare Modelle, gemeinsame Datenstrukturen, transparente Unsicherheit, reproduzierbare Tests und eine klarere Verbindung von Planung → Simulation → Konstruktion → Fertigung.

# Workstreams

## A. Schema 3.0

- Feldweise Provenienz statt nur Quelle pro Datensatz.
- Quellenstatus MANUFACTURER, RETAILER, MEASURED, USER, DERIVED.
- Abrufdatum, Dokumentversion, Artikelnummer, discontinued, Nachfolgemodell.
- Mess-/Herstellerwerte niemals gegenseitig überschreiben.

### Abnahme A
- [ ] Feldprovenienz speicherbar.
- [ ] Migration alter Daten.
- [ ] Konflikte sichtbar.

## B. Driver Coverage

- Subwoofer, Woofer, Midwoofer, Midrange, Fullrange, Tweeter, Compression, Coax abdecken.
- Ziel: mindestens 100 enclosure-ready und möglichst viele crossover-/manufacturing-ready reale Chassis, sofern Quellen vorhanden.
- Keine erfundenen FRD/ZMA/Montagemaße.

### Abnahme B
- [ ] Coverage-Report steigt materiell.
- [ ] Testdaten klar getrennt.
- [ ] Unvollständige Chassis bleiben sichtbar, aber korrekt eingeschränkt.

## C. Passive/Port/Hardware Library

- Passivmembranen mit Mms/Xmax/Fläche/Montagemaßen.
- Aeroports/Rohre mit realen Geometrien, wenn verfügbar.
- Terminals, Speakon, Binding Posts, Schrauben, Inserts, Kabel, Kleber.
- Port/Hardware-Kompatibilität modellieren.

### Abnahme C
- [ ] Neue Kategorien nutzbar.
- [ ] BOM kann reale Positionen auswählen.
- [ ] Kompatibilität testbar.

## D. Crossover Component Catalog

- R/L/C mit E-Reihe, Toleranz, Belastbarkeit, DCR/ESR soweit bekannt.
- Sollwert vs. konkretes Bauteil trennen.
- Preisstatus und Lieferstatus als Snapshot.

### Abnahme D
- [ ] Weichenentwurf kann reale Standardwerte wählen.
- [ ] DCR/ESR fließt optional in Simulation ein.

## E. Amplifier & DSP Catalog

- Plate Amps, DSPs, Aktivmodule und Mehrkanalverstärker als neue Komponententypen.
- Kanäle, Leistung, Impedanzbereich, DSP-Funktionen, Maße, Preis.

### Abnahme E
- [ ] Aktive Projekte vorbereitbar.
- [ ] BOM kennt diese Komponenten.

## F. Library UX & Audit

- Filter nach Readiness, Hersteller, Größe, Preis, Typ, Trust.
- Detailansicht zeigt fehlende Felder.
- Importprüfung mit Dry-Run und Konfliktbericht.

### Abnahme F

# Architekturregeln

- Core/Domain darf nicht von PySide6 abhängen.
- Solver, Optimierer, Library und Geometrie bleiben separat testbar.
- Einheiten intern SI.
- UI formatiert Werte und Einheiten.
- Projektdatei erhält bei Schemaänderungen Migrationen.
- Ein einziges kanonisches Projektmodell.
- Keine doppelte Geometrie für UI und Fertigung.
- Datenprovenienz bleibt erhalten.
- Fehlerzustände werden als strukturierte Objekte modelliert, nicht nur als freie Strings.
- Ergebnisse müssen reproduzierbar sein.
- Zufallsbasierte Optimierung nur mit explizitem Seed und dokumentierter Deterministik.

---

# Daten- und Vertrauensregeln

- Reale Daten brauchen Quelle, Abruf-/Messdatum und Status.
- Abgeleitete Werte müssen als abgeleitet gekennzeichnet werden.
- Schätzwerte dürfen niemals still wie Herstellerdaten aussehen.
- Datenvollständigkeit beeinflusst Assistent und Score.
- Aussagen wie „beste“, „günstigste“, „lauteste“ oder „linearste“ sind nur zulässig, wenn die Vergleichsgrundlage vollständig genug ist.
- Für experimentelle Modelle wird im Projekt und Export ein Vertrauensstatus mitgeführt.
- Der Nutzer muss erkennen können, welche Teile gemessen, berechnet, geschätzt oder unbekannt sind.

# Detailed Execution Extension

## User Journeys

### Journey 1 – Find a truly usable woofer
Filter for 6.5-inch midwoofer, manufacturing-ready + crossover-ready, max price, known mounting depth. Results must exclude incomplete records instead of silently filling gaps.

### Journey 2 – Audit an incomplete catalog record
Open a retailer-only entry. The detail page explains exactly which fields are missing, which capabilities are blocked, and where every known field came from.

### Journey 3 – Update manufacturer data
A newer datasheet conflicts with retailer values. The import preview shows field-level differences and lets the trusted manufacturer source supersede the retailer value without deleting history.

## Provenance Model

Each technical field may carry:
- value
- unit
- source type
- source URL/document
- retrieved date
- document revision
- verification state
- optional notes

Do not clone this metadata manually across every Pydantic field if a reusable FieldEvidence structure is cleaner.

## Completeness Rules

Define required-field sets by role and use-case. A tweeter's enclosure readiness differs from a woofer's. A compression driver's geometry requirements differ from a cone driver. Readiness must therefore be capability-specific, not a single global percentage.

## Search / Indexing

Prepare indexing for:
- manufacturer
- model
- size
- impedance
- driver type
- price range
- readiness
- Fs/Qts/Vas ranges
- cutout/mounting depth
- frequency coverage

Do not optimize by loading thousands of JSON files repeatedly per keystroke.

## Import Governance

Imports need:
- dry-run
- add/update/skip counts
- field conflict list
- invalid records
- duplicate detection
- rollback on failed batch
- source attribution

## Library Evidence

Produce before/after statistics and at least:
- full driver detail;
- incomplete driver detail;
- conflict preview;
- readiness-filtered search;
- crossover part catalog;
- DSP/amp catalog.

## Performance

Benchmark 100, 1000 and 5000 synthetic metadata records without pretending those synthetic records are real library content.

## Additional Acceptance

- [ ] Field provenance survives save/load.
- [ ] A retailer import cannot silently replace a verified manufacturer field.
- [ ] Readiness rules are tested per component type.
- [ ] Library search remains responsive at projected scale.
- [ ] Test/demo records are impossible to confuse with real products in UI/export.
