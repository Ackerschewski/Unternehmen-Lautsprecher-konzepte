# Architekturregeln

- Core/Domain darf nicht von PySide6 abhängen.
- Solver, Optimierer, Library und Geometrie bleiben separat testbar.
- Einheiten intern SI.
- UI formatiert Werte und Einheiten.
- Projektdatei erhält bei Schemaänderungen Migrationen.
- Ein einziges kanonisches Projektmodell.
- Keine doppelte Geometrie für UI und Fertigung.
- Datenprovenienz bleibt erhalten.
- Fehlerzustände werden als strukturierte Objekte modelliert, nicht nur als freie Strings.
- Ergebnisse müssen reproduzierbar sein.
- Zufallsbasierte Optimierung nur mit explizitem Seed und dokumentierter Deterministik.

# Daten- und Vertrauensregeln

- Reale Daten brauchen Quelle, Abruf-/Messdatum und Status.
- Abgeleitete Werte müssen als abgeleitet gekennzeichnet werden.
- Schätzwerte dürfen niemals still wie Herstellerdaten aussehen.
- Datenvollständigkeit beeinflusst Assistent und Score.
- Aussagen wie „beste“, „günstigste“, „lauteste“ oder „linearste“ sind nur zulässig, wenn die Vergleichsgrundlage vollständig genug ist.
- Für experimentelle Modelle wird im Projekt und Export ein Vertrauensstatus mitgeführt.
- Der Nutzer muss erkennen können, welche Teile gemessen, berechnet, geschätzt oder unbekannt sind.

# Detailed Execution Extension

## User Journeys

### Journey 1 – Active monitor
Select active 2-way. Program chooses/accepts DSP + amplifier channels, creates HP/LP, EQ and delay, then simulates acoustic sum and exports generic biquads.

### Journey 2 – Protected subwoofer
Given Xmax/Pe and amplifier limits, propose subsonic HP and limiter guidance. Clearly state that the limiter is an engineering starting point, not certified driver protection.

### Journey 3 – Compare passive vs active
Same drivers/enclosure: compare BOM, cost, amplifier requirements, target response, losses and complexity.

## DSP Numeric Contract

Every digital filter must define:
- sample rate
- filter type
- parameters
- coefficient convention
- channel
- enabled state

Exports must document coefficient ordering/normalization.

## Headroom

Track:
- input reference
- per-filter peak gain
- channel gain
- expected headroom
- clipping risk

Do not display a numerical clipping margin if source voltage/calibration is unknown.

## Delay / Alignment

Represent delay in seconds internally and allow ms/sample UI. Acoustic center offsets may be converted to delay but must preserve whether value is geometric or user-tuned.

## Export Verification

For each supported target export, re-import or independently evaluate when possible and compare response to internal DSP chain.

## Active BOM

Include:
- DSP
- amp channels/module
- power supply where explicit
- connectors
- wiring notes

Unknown accessories remain missing, not automatically priced.

## Additional Acceptance

- [ ] Internal biquad convention documented.
- [ ] Exported filters numerically match internal response.
- [ ] Passive/active comparison uses comparable cost coverage.
- [ ] Headroom unknown state works.
- [ ] Delay provenance (geometry/manual/optimizer) is preserved.
