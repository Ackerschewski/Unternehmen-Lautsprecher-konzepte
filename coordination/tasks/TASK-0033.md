# Detailed Execution Extension

## User Journeys

### Journey 1 – Measured 2-way
Import woofer/tweeter FRD+ZMA, choose target, let optimizer propose crossover, then compare theoretical component values with mapped real E-series components.

### Journey 2 – 3-way manual/expert
Expert edits a midrange bandpass branch, sees acoustic sum and input impedance update, then checks component power/current constraints.

### Journey 3 – Data-poor design
If only nominal impedance exists, the app may offer a preliminary electrical network but clearly disables claims about final acoustic summation.

## Netlist Requirements

Represent topology independent of UI. Components and nodes need stable IDs. Branch labels are presentation metadata, not simulation logic.

Support:
- series/parallel networks
- driver load nodes
- correction networks
- polarity/delay metadata
- component parasitics where known

## Optimization Objectives

Possible weighted terms:
- target magnitude error
- crossover region smoothness
- directivity mismatch when available
- impedance minimum
- phase behavior
- component count
- component cost
- sensitivity loss

No single hard-coded "best crossover".

## Component Stress

Where source data permits:
- resistor dissipation
- inductor RMS current
- capacitor RMS voltage
- amplifier load

If source excitation/power is unknown, mark stress as not calculated.

## Tolerance Analysis

Add optional Monte Carlo / worst-case preview using component tolerances. Keep deterministic seed for tests. Show envelope, not fake exact certainty.

## Additional Acceptance

- [ ] General netlist can represent existing 2/3-way projects.
- [ ] Real ZMA changes calculated transfer compared to nominal resistance.
- [ ] Acoustic optimization refuses unsupported fullrange claims without FRD.
- [ ] Real component mapping reruns the simulation.
- [ ] Component stress and tolerance analysis are optional but structured.
