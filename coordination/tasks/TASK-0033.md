Baue eine allgemeine passive N-Wege-Netlist, akustische Summierung, reale Bauteilwahl und nachvollziehbare Optimierung für 1–4 Wege.

# Warum dieses Paket nötig ist

Die bisherige 2-/3-Wege-Weiche muss zu einem echten akustischen Weichenstudio werden, das reale FRD/ZMA, Phase, Impedanz und Standardbauteile gemeinsam optimiert.

Der aktuelle Stand ist bereits funktionsreich. Der nächste Qualitätssprung entsteht nicht durch weitere isolierte Buttons, sondern durch belastbare Modelle, gemeinsame Datenstrukturen, transparente Unsicherheit, reproduzierbare Tests und eine klarere Verbindung von Planung → Simulation → Konstruktion → Fertigung.

# Workstreams

## A. General Netlist

- R, L, C, Serien-/Parallelzweige, Zobel, Notch, L-Pad, Baffle-Step, Shelving.
- 1-, 2-, 2.5-, 3- und 4-Wege abbildbar.
- DCR/ESR optional.

### Abnahme A
- [ ] Netlist serialisierbar.
- [ ] 2-/3-Wege Altprojekte migrieren.
- [ ] Referenztests.

## B. Complex Load Simulation

- ZMA als komplexe Last.
- Spannung/Phase je Treiber.
- Gesamteingangsimpedanz.
- Mindestimpedanz und kritischer Phasenwinkel.

### Abnahme B
- [ ] Komplexe Simulation korrekt.
- [ ] Amp-Kompatibilitätswarnungen.

## C. Acoustic Sum

- FRD + elektrische Filterantwort + Phase.
- Schallzentren/Abstände und Polarität.
- Delay.
- Ohne Phase vereinfachte Bewertung klar kennzeichnen.

### Abnahme C
- [ ] Woofer/Mid/Tweeter/Summe sichtbar.
- [ ] Phase sauber behandelt.

## D. Automatic Optimization

- Zielkurve.
- Variablen: Werte/Topologie/Trennfrequenzen/Polarity.
- Constraints: Impedanz, Bauteile, Leistung, Frequenzbereiche.
- Mehrere Optimierungsziele.

### Abnahme D
- [ ] Deterministisch reproduzierbar.
- [ ] Score-Breakdown.
- [ ] Keine unplausiblen Werte.

## E. Real Component Mapping

- Sollwert auf reale E-Reihe / Bibliothek abbilden.
- DCR/ESR und Toleranz erneut simulieren.
- BOM direkt erzeugen.

### Abnahme E
- [ ] Theorie vs. reale Bauteile vergleichbar.
- [ ] Abweichung sichtbar.

## F. Crossover Studio UI

- Schaltplan, Kurven, Impedanz, Bauteilliste, Optimizer.
- Manuelle Bearbeitung mit Undo.
- A/B-Vergleich.

### Abnahme F
- [ ] Keine monolithische Dialogdatei.
- [ ] Sound Lab Integration.

# Architekturregeln

- Core/Domain darf nicht von PySide6 abhängen.
- Solver, Optimierer, Library und Geometrie bleiben separat testbar.
- Einheiten intern SI.
- UI formatiert Werte und Einheiten.
- Projektdatei erhält bei Schemaänderungen Migrationen.
- Ein einziges kanonisches Projektmodell.
- Keine doppelte Geometrie für UI und Fertigung.
- Datenprovenienz bleibt erhalten.
- Fehlerzustände werden als strukturierte Objekte modelliert, nicht nur als freie Strings.
- Ergebnisse müssen reproduzierbar sein.
- Zufallsbasierte Optimierung nur mit explizitem Seed und dokumentierter Deterministik.

---

# Daten- und Vertrauensregeln

- Reale Daten brauchen Quelle, Abruf-/Messdatum und Status.
- Abgeleitete Werte müssen als abgeleitet gekennzeichnet werden.
- Schätzwerte dürfen niemals still wie Herstellerdaten aussehen.
- Datenvollständigkeit beeinflusst Assistent und Score.
- Aussagen wie „beste“, „günstigste“, „lauteste“ oder „linearste“ sind nur zulässig, wenn die Vergleichsgrundlage vollständig genug ist.
- Für experimentelle Modelle wird im Projekt und Export ein Vertrauensstatus mitgeführt.
- Der Nutzer muss erkennen können, welche Teile gemessen, berechnet, geschätzt oder unbekannt sind.
